## Part B — the composed-latency bug fix: verified real, not merely asserted

### Claim 1 — start point was wrong (endpoint-commit instead of last-VAD-frame)

Read `git diff main -- backend/src/voice_agent/orchestration/turn_flow.py` (empty — `commit_endpoint()` already emitted `USER_SPEECH_ENDED` with payload `{last_speech_at_ms, committed_at_ms}` before this branch; the payload data existed, it just wasn't the field being read). `commit_endpoint()` calls `rt.emit(...)` synchronously at endpoint-commit time, so the event envelope's `occurred_at` ≈ `committed_at_ms` — i.e. **after** the docs/11 §11 "~700-1000 ms endpoint stage," not at the real last-speech instant. `git diff main -- backend/src/voice_agent/events_and_latency/latency.py` confirms the pre-existing code computed `FIRST_AUDIBLE_RESPONSE` from `_between(speech_end.occurred_at, playback.occurred_at)` — using the envelope wall-clock time, which is the committed/endpoint-stage-inclusive-omitting time, not `last_speech_at_ms`. The new code (`first_audible.py::worker_span_ms`) reads `USER_SPEECH_ENDED.payload["last_speech_at_ms"]` directly — the true worker-monotonic VAD timestamp — confirming the claimed bug and fix are both genuine.

### Claim 2 — end point had no browser/network component

`git diff main -- backend/src/voice_agent/agent_worker/speech_output.py` confirms `PLAYBACK_STARTED`'s payload previously carried no first-frame timestamp at all; the fix adds `_record_started()`, which captures `self._deps.clock.monotonic_ms()` at the exact moment the first frame is written and stores it as `first_frame_at_ms` in the event payload. This is the worker-side end of the composed span (docs/06 §15). The browser/network components are new entirely (`transport.quality_updated` with `aggregate: "turn_latency_sample"`, sourced from the new `client.latency_sample`); there is no way the pre-existing code could have included them since the frontend previously never sent that event (confirmed: `frontend/src/session/latencySamples.ts` and its wiring into `controller.ts` are new in this branch's diff).

### Three-tier composition logic — read and independently traced

`backend/src/voice_agent/events_and_latency/first_audible.py::compose()`: `COMPOSED` (measured network, `network_uncertainty_ms == network_one_way_ms`, since the true one-way delay of an RTT/2 estimate on an asymmetric path lies in `[0, RTT]`), `COMPOSED_NETWORK_ASSUMED` (no browser-reported network estimate: uses the documented Decision 066 fallback `ASSUMED_NETWORK_ONE_WAY_MS = 100`, `ASSUMED_NETWORK_UNCERTAINTY_MS = 250` — never treats the missing component as zero), `WORKER_ONLY` (no browser span at all: diagnostic lower bound, `is_composed == False`, excluded from gate evidence). `backend/tests/unit/events_and_latency/test_first_audible.py` independently proves all three tiers with concrete numeric assertions (e.g. `test_a_missing_network_estimate_uses_the_documented_fallback_and_is_flagged` asserts `total_ms == 1_400 + 120 + ASSUMED_NETWORK_ONE_WAY_MS`, not a stub `+0`), proves negative cases (negative components raise, booleans are rejected as not-integers, first-frame-before-last-speech is rejected, legacy `playback.started` without `first_frame_at_ms` yields no sample — never a fabricated zero), and proves the breakdown (`first_audible_breakdown`) keeps `composed_all` percentiles strictly separate from `worker_only_diagnostic` and reports `meets_composed_method` honestly.

## Cross-stack wire-shape check — `client.latency_sample` / `transport.quality_updated`

Read both sides directly (not inferred from docs, since docs/01/02 name the events but do not freeze their payload field names):

| Field | Backend (`first_audible.py`) | Frontend (`controller.ts` / `latencySamples.ts`) | Match |
|---|---|---|---|
| browser playout key | `BROWSER_PLAYOUT_KEY = "browser_playout_ms"` | `{ browser_playout_ms: sample.browserPlayoutMs }` | yes |
| network key | `NETWORK_ONE_WAY_KEY = "network_one_way_ms"` | `{ ..., network_one_way_ms: sample.networkOneWayMs }` only when `sample.networkOneWayMs !== null` | yes |
| aggregate tag | `AGGREGATE_KEY = "aggregate"`, value `"turn_latency_sample"` | recorded as `transport.quality_updated` by the worker from the client event, not set by the browser | consistent (browser sends the two numeric fields; the worker tags the durable aggregate) |
| turn_id requirement | `first_audible_sample(turn_id, ...)` — the worker always scopes by turn | `emitLatencySample(turnId: string, ...)` takes a non-optional `turnId`; `LatencySampleTracker.onPlaybackStarted(turnId: string \| null)` returns immediately if `turnId === null` | yes — never sent without a turn id |
| once-per-turn | `_browser_report()` takes only the turn's first matching event | `sentTurnIds: Set<string>` — `onPlaybackStarted` is a no-op if the turn id is already in the set or already active | yes |
| omit-not-zero on missing network | `latency_sample_payload(playout, None)` omits the key entirely (`payload["network_one_way_ms"]` only set `if network_one_way_ms is not None`) | `networkOneWayMs === null ? {browser_playout_ms} : {browser_playout_ms, network_one_way_ms}` — key is absent, never `0`/`null` | yes |

`npx tsc --noEmit` and the full `pytest` run both passed with this wiring in place, and `frontend/tests` include coverage of `latencySamples.ts` (94.3% statements) and `controller.ts`'s latency-emission path. One terminology note, not a defect: the code comment in `latencySamples.ts` states "a worker-opened greeting has one [turn_id]; a turn this worker did not open does not" — i.e. the skip-when-null rule exists for turns the browser's worker instance did not open (e.g. a replacement agent after recovery), not specifically for the greeting as the task brief's phrasing suggested. ## Holdout isolation — mechanism read directly, not just asserted by a test

`selection.py::select_cases()` filters by `loadable_splits()`, which for a `DEVELOPMENT`-purpose run never includes `EvaluationSplit.HOLDOUT` — holdout cases are **not present in the tuple returned to the runner at all** for a development run; they are not merely flagged and skipped later. `holdout_authorized()` raises `HoldoutAccessError` unless `purpose is RELEASE` **and** `release_candidate` is named **and** `unseal_holdout=True` is explicit. `test_offline_runner.py::test_development_run_executes_only_development_cases_offline` goes further than unit-testing the selection function in isolation: it runs the **actual runner** end to end and asserts `{key for key, _ in executed} & {"txt-006", "txt-012", "rel-092", "rel-094"} == set()` against the real list of cases that reached the scripted engine/reliability executor — i.e. it proves no holdout case reached an executor in a real run, not merely that a flag was set correctly. `test_holdout_is_refused_without_an_unsealed_release_candidate` proves the refusal path for both a development-purpose and an un-unsealed release-purpose request.
