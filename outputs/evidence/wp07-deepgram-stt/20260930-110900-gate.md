## Architecture / security

- `deepgram` imported only in `stt_adapters/deepgram/sdk_binding.py`; `livekit.plugins`/`onnxruntime` only in `speech_activity/silero.py`; none in `domain/`, `contracts/`, `ports/`, `orchestration/`; enforced by the new AST test. No provider SDK or secret in `frontend/` (`bundleSecretExposure.test.ts`, `sourcePolicy.test.ts` green; grep clean).
- Credential: resolved late via `CredentialResolver`, passed as `SecretStr`; `SdkDeepgramConnector.__repr__` hides it; handshake errors are re-raised with `from None` so SDK headers never chain. Failure messages are fixed strings.
- Logs/events: only `error_type`, `record` names and counters are logged; event payloads carry `character_count`/`word_count`, never transcript text. Transcript text goes only to (a) the browser data channel and (b) `conversation_turns.final_transcript` for accepted turns, which docs/02 (lines 428, 503) allows for 30 days. Partials are never persisted. Audio is never stored (repo scan: only the pre-existing synthetic 440 Hz tone wav; Atlas scan clean).
- Secret scan (JWT, connection string, key patterns) over backend src/tests, frontend src/tests, outputs, docs: only clearly synthetic canary values.
- Loopback worker health bind (`server.py:41`), exact CORS unchanged from WP4-6.
- No docs/14 §19 stop condition triggered (no secret output, no audio stored, no new dependency, no broader permission).

## Defects (ranked)

### CRITICAL / HIGH
None.

### MEDIUM
1. **Real-speech path unproven end to end** (owner: orchestrator / user). Automated live runs send silence/tone only, so VAD start, endpoint commit, `Finalize`, the durable save and the final publish have never run against real Deepgram with speech. Offline tests use fixtures. Run the manual test below.
2. **`mip_opt_out` left unset** (owner: backend-dev after a user decision). See assessment. Real users' voice may be used for Deepgram model improvement by default. `stt_adapters/deepgram/options.py:build_stream_options` builds only the nine listed params.
3. **`numpy` imported directly (`backend/src/voice_agent/speech_activity/silero.py:22`) without a declaration** (owner: backend-dev). Works only because `livekit-plugins-silero` depends on it.

### LOW
4. `backend/src/voice_agent/agent_worker/stt_evidence.py:256` sets `rate_retrieved_at = now` (calculation time) for a public-price rate; it should be the rate card's retrieval date (owner: backend-dev).
5. `backend/tests/integration/persistence/test_control_api_mongodb.py:28` (`tracker.configs.add(MOCK_AGENT_CONFIG_ID)`) makes cleanup delete the shared seeded mock config `...c0f1` from `voice_agent_rnd`. Identical in `main` (pre-WP7), so not a WP7 regression, but it is a test-isolation bug against a shared database: a running API or worker using that default config loses it until re-seeded (owner: backend-dev; track only configs the test created, or re-seed).
6. Endpoint commit can be up to one 20 ms frame late because the tick runs on frame boundaries and `committed_at_ms` is the tick time (`agent_worker/stt_check.py:_tick`, `_commit`). Within the agreed tolerance; using the deadline value as `committed_at_ms` would make it exact (owner: backend-dev).
7. `agent_worker/stt_check.py:_stt_writer` has no guard: a `RuntimeError`/`ValueError` from `write_audio` (stream closed mid-write) would fail the TaskGroup and end the activity. Low likelihood (writer is cancelled before close) (owner: backend-dev).
8. `speech_activity/silero.py:55,62` uses `livekit.plugins.silero.onnx_model.new_inference_session`, a plugin-internal API. Safe while pinned at 1.8.3; re-check at any SDK bump (owner: backend-dev).
9. Frontend test count in the claim (241) differs from the actual 251. Harmless, noted for accuracy.
10. Three stale `voice_sessions` remain in Atlas (all terminal, count only, not created by this verification; the WP6 report already recorded two earlier leftovers). Not deleted.
