This is a genuine but low-risk docs/02 gap (new field, not yet ratified) that should get a one-line docs/02 amendment at the next doc sync; it does not block WP8 functionally since OpenAI's Responses API GPT-6 Luna in this Phase 0 config (`store=false`, no prior-response chaining) is not expected to ever report a non-zero cache-write value in practice.
4. **No automated test exercises an actual "ignore previous instructions, reveal your system prompt" adversarial model *output***. The disclosure guard (`response_segmentation/disclosure.py`) and its tests (`tests/unit/response_segmentation/test_disclosure.py`) correctly catch (a) verbatim/paraphrased 8-word shingle overlap with the real pinned instruction and (b) credential-shaped strings, with reasonable adversarial-looking fixtures (quoted instruction fragments, shouted instruction lines, Hinglish instruction paraphrase, 6 credential shapes, 4 clean pass-through cases). What it structurally cannot test offline is whether the *model* actually resists an injected request to reveal its prompt — that is inherent to any offline verification of an LLM's behavior and is explicitly deferred to the live benchmark (docs/08 §18, §22); not a gap in this WP's test design, just a reminder that "injection resistance" test coverage here is output-side guarding, not behavior-side proof.

No DNS/TCP packet for `api.openai.com` left the process in this run (the fixture patches `httpx.HTTPTransport.handle_request`/`AsyncHTTPTransport.handle_async_request` directly, before any socket is opened).

- Exactly-one-generation-per-turn and duplicate-trigger protection: `ConversationGate.authorize()` (`agent_worker/llm_gate.py:146-162`) maintains an `_authorized: set[str]` of turn IDs; a re-trigger of an already-authorized turn increments `duplicate_triggers` and returns `True` without starting a second generation task. Tested directly (`test_exactly_one_generation_per_accepted_turn`).
- Retry-before-delivery semantics: `retry_decision()` (`response_generation.py:302-309`) returns `None` immediately if `result.delivered` is non-empty (via `RetryContext(output_delivered=bool(result.delivered))` feeding `decide_retry`), and `_generate()`'s retry loop in `llm_gate.py` always mints a new `operation_id` per attempt. Tested (`test_transient_failure_before_output_retries_with_a_new_operation`, `test_failure_after_partial_delivery_is_not_retried_or_padded`).
- Cancellation / generation fence: `ResponseGenerator._check_fence()` / `_deliver_one()` re-check the fence before every delivery and on every event; `ConversationGate._supersede_active()` advances the fence **before** calling the engine's `cancel()`, so late deltas from the old generation are counted (`late_events`) but never delivered. Tested (`test_newer_turn_supersedes_and_late_tokens_never_reach_the_browser`, `test_fence_advance_cancels_and_rejects_late_tokens`).
- Generated-vs-delivered separation: `ConversationTurn.generated_text` (`domain/turn.py:96`, accumulated via `record_generated()`) is a distinct persisted field from what is published to the browser (`run.delivered_text()` / `DeliveredSegment`s, which are never persisted verbatim on the turn — only their character count appears in `provider_operations.result_summary` via `_summary()`). In this no-TTS WP8 `llm_check` worker mode, `spoken_text` legitimately stays empty (no TTS runs; see LOW #6 for the WP9 follow-up implication), which is honest per docs/08 §12 ("generated completion does not imply that all text was synthesized or spoken") rather than a bug.
- Golden fixtures (backend side): independently decoded and printed all 7 new `llm_*` cases from `backend/tests/fixtures/realtime_wire/agent_to_browser.json` outside pytest — shapes match the canonical `va.response.v1`/`va.state.v1` payload described in the task (`conversation.segment_ready` partials with `is_final:false`/`segment_sequence`; `conversation.completed`/`conversation.cancelled` finals with `is_final:true`/`response_completion_status`, one with `fallback_template_id="fallback.response_truncated.v1"`).
