## Defects (ranked)

1. **HIGH — Missing cache-write token usage unit, rate, and normalization (cost model incomplete vs docs/15 §2.4 / docs/08 §255,§325).**
   `backend/src/voice_agent/contracts/usage.py:20-31` (no `CACHE_WRITE_TOKENS` in `UsageUnit`), `backend/src/voice_agent/costing/rate_card.py:92-117` (`_shared_rates()` has no cache-write `UnitRate`), `backend/src/voice_agent/costing/usage_normalization.py:52-70` (`llm_usage()` signature has no `cache_write_tokens` parameter).
   Owner: backend-dev.
   Impact: if OpenAI ever returns cache-write token usage (prompt caching writes), it is silently dropped rather than priced or reported as missing/unavailable — this could under-report real spend and violates the "never becomes zero, never silently dropped" usage principle for a meter that docs explicitly require.
   Suggested fix: add `UsageUnit.CACHE_WRITE_TOKENS`, an OpenAI rate line at `0.125` USD/1M in `rate_card.py`, and a `cache_write_tokens` parameter to `llm_usage()`, with a fixture test asserting the docs/15 §2.4 formula end-to-end.

2. **MEDIUM — No direct test proves "fallback-only turns are excluded from conversation history."**
   `backend/tests/integration/test_mock_pipeline.py::test_empty_transcript_with_fallback_speaks_clarification` (lines 320-336) checks `fallback_used`/`input_disposition`/TTS request but never asserts on `harness.orchestrator.report.history`. The behaviour is implemented correctly (`turn_lifecycle.py:104-113`), but docs/14 §8 explicitly calls for history-rule tests, and this specific rule (docs/08 §7 "history excludes ... failed/unplayed TTS responses" combined with fallback turns never reaching `input_disposition = accepted`) is currently unverified by any assertion.
   Owner: backend-dev (or whoever owns `tests/integration/test_mock_pipeline.py`).

3. **MEDIUM — `reporting_currency` default is INR in the runtime/test harness, ahead of Decision 016's USD-normalized stored-cost convention.**
   `backend/src/voice_agent/orchestration/runtime.py:77`, `backend/tests/integration/conftest.py:151`.
   Not a WP2 code defect (no `cost_entries` persistence exists yet to violate), but flagged so WP5/WP11 don't inherit INR-as-default for the durable record without an explicit decision.
   Owner: backend-dev, for follow-up in WP5/WP11.

No CRITICAL or LOW-severity findings beyond the above.
