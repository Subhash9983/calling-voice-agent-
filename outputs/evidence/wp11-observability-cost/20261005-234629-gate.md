### The claimed-fixed flaky test (`test_fixed_and_canonical_values_are_enforced[agent_config_id-12]`) — confirmed real, confirmed fixed

`request_id` is generated via `str(uuid.uuid4())` (`backend/src/voice_agent/control_api/request_context.py:27`) — i.e. genuinely random per request, so the old assertion `assert str(value) not in response.text` could spuriously fail whenever the random UUID happened to contain the literal substring `"12"` (a ~1-in-8 chance per hex digit position across a 32-hex-digit UUID, a real and non-negligible flake rate over CI history). The fix (`git diff main -- backend/tests/integration/control_api/test_sessions.py`) strips the actual `request_id` out of the response body before asserting the value is absent:
```python
echoed = response.text.replace(response.json()["request_id"], "")
assert str(value) not in echoed
```
This is the correct fix (the field under test is genuinely never echoed; only the unrelated random ID could coincidentally match). Ran the parametrized test 5 consecutive times in isolation — 6/6 cases passed every time — and 3 full-suite runs show 2869/2869 passed with no flake recurrence. **Confirmed genuine, confirmed fixed, not merely claimed.**

### #1 — Cost lines had no turn_id/logical_request_id link

Genuine.

### #2 — `AttemptCostLedger`: dedupe, late-usage supersede, post-finish re-issue — **real, and the most substantively verified claim in this WP**

Read `backend/src/voice_agent/costing/attempt_ledger.py` in full. `settle()` compares the new `MeteredUsage` against the previously stored one for the same `operation_id` by dataclass equality and returns `()` (no new entries) when unchanged — a genuine no-op on a repeated settle. Late usage (a different `MeteredUsage` for an already-settled `operation_id`) increments `calculation_version` from the prior run and sets `supersedes_calculation_run_id` to the prior run's ID, rather than adding a second line. `session_run()` only re-prices when `self._session_stale` is true (set exactly once per genuinely new/changed attempt).

Tests directly proving this, not merely exercising the happy path:
- `test_a_repeated_settle_never_double_counts_the_session` — settles the same two attempts a second and third time, asserts both replays return `()`, and the session total is unchanged at `Decimal("0.000425")`. **This would fail under a naive "always append" implementation** (the session total would double or triple).
- `test_late_usage_supersedes_the_attempt_and_the_session_run` — settles an attempt, computes a session run, then settles the *same* attempt again with different (higher) usage, and asserts `calculation_version == 2`, `supersedes_calculation_run_id` points at the original run, and the final total (`0.000455`) reflects only the latest usage, not the sum of both. **This would fail if late usage were added on top of the original** (total would be `0.00065`, not `0.000455`).
- In production wiring (`agent_worker/stt_evidence.py::operation_settled`), a check `if self._finished: await self._write_costs(self._ledger.session_run)` re-issues the session run when evidence settles *after* `finish()` has already run — confirmed by the dedicated unit test `test_late_usage_after_finish_supersedes_the_session_run` (`tests/unit/agent_worker/test_attempt_evidence.py`).

All three sub-claims (dedupe, late-usage supersede, post-finish re-issue) are genuine and independently test-proven, not just asserted in the module docstring.

## Resolved ambiguities — sanity-checked

- **STT-stream/LiveKit attempts have no `turn_id` (session-wide); turn-level cost excludes them, session-level cost does not.** Confirmed directly in `costing/reconciliation.py::_by_turn()`: an operation with `turn_id is None` is added to `unattributed_usd`, not dropped, and `session_total_usd` is independently derived from the full session-scope cost run (which prices *every* settled attempt, STT/transport included) while `attempt_total_usd` is the sum of *all* attempt costs (again including STT/transport). The dedicated test `test_turn_session_and_attempt_totals_agree` (`tests/unit/costing/test_reconciliation.py:115`) makes this explicit with real numbers: `session_total_usd == attempt_total_usd == Decimal("0.0214")` (STT `0.0184` + TTS `0.003`), `turn_totals_usd == {TURN: Decimal("0.003")}` (TTS only), and `unattributed_usd == Decimal("0.0184")` (the session-level STT stream) — i.e. the STT cost is correctly present in the session total and correctly absent from the turn breakdown, never silently excluded from the session figure. Confirmed sound.
- **"Retry/failure-related cost" = failed/timed-out/cancelled attempts; a successful retry counts as normal cost.** Confirmed: `reconciliation.py::_RETRY_OR_FAILURE = frozenset({FAILED, TIMED_OUT, CANCELLED})`, and `_is_retry_or_failure()` checks only the operation's own terminal status — a successful retry attempt (status `SUCCEEDED`) is never counted, confirmed by `test_turn_session_and_attempt_totals_agree`'s `retry_or_failure_usd == Decimal("0.0015")` (the failed TTS attempt's cost only, not the subsequent successful one).
- **`/costs` still uses only the latest final run per docs/02 §10.** Confirmed: `latest_runs()` in `reconciliation.py` and the pre-existing `latest_final_run`/`_latest_charges` dedup logic in `cost_entries.py` both select strictly by `(calculation_version, calculation_run_id)` maximum per scope target — no change to this invariant, and `test_superseded_runs_are_never_added_together` directly proves superseded versions are excluded, not summed.
- **`recoverable` = retryable-classified vs. `recovered` = later-attempt-succeeded.** Confirmed in `control_api/services/reads.py::_recovered_requests()` — a bounded scan (`MAX_RECOVERY_PAGES = 5` pages of 100) over the timeline for a later successful attempt of the same `logical_request_id`; distinct from `ErrorEventRecord.retry.retryable` (set at error-classification time, independent of whether a retry was ever attempted or succeeded). `error_summary.recoverable`/`.recovered` in `evidence_audit.py`/`session_evidence.py` keep these as two independently-computed counters, matching the stated distinction (confirmed by reading `_error_counts()` in `projections.py`, which surfaces both `recoverable` and `recovered` as separate fields rather than conflating them).
- **Retention evidence as local report files, not a new collection.** Confirmed: `persistence/mongodb/repositories/retention_evidence.py`'s own module docstring states "Nothing is written or deleted here," and the class contains only read (`find`/`count_documents`-style) operations over the existing `ix_sessions_expiry` index and existing collections (`VOICE_SESSIONS`, scoped children) — no new collection name appears in `collection_names.py`'s diff. Consistent with docs/02 §20's "no audit collection" naming.
