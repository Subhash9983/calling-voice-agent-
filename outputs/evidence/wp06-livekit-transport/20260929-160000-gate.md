A manual human browser test is still required to close it.

## Architecture / security

- `livekit.api` only in `transport_adapters/livekit/control.py`; `livekit.rtc`/`agents` only in `rtc_binding.py`, `agent_worker/entrypoint.py`, `agent_worker/server.py`; none in `domain/`, `contracts/`, `ports/`, `orchestration/`. Enforced by the AST test `unit/test_livekit_boundaries.py`, confirmed by grep.
- Secret scan (JWT, connection string, key patterns) across `backend/src`, `backend/tests`, `frontend/src`, `frontend/tests`, `outputs`: only clearly synthetic canary values in tests. Built `frontend/dist` contains no `LIVEKIT_API_SECRET` or `MONGODB_URI`.
- CORS: `app.py:177-181` exact single origin, methods GET/POST, header content-type, credentials off. Worker health endpoint binds `127.0.0.1`. SDK loggers pinned to WARNING with a safe JSON formatter.
- Timeouts: LiveKit control calls 8 s (`runtime.py:78`, `common.py:130,165`); store calls stay 2 s.
- Contract consistency (read both sides): envelope keys, `state`, `text`/`is_final`, playback identity trio, `position_ms`, `client.*` and `playback.*` event names, schema_version 1, size limits and rate numbers agree. Metrics heartbeat (1 s) feeds the 5 s frontend watchdog. Frontend and backend reconnect windows are both 20 s. The TypeScript encoder is never run against the Python decoder (defect 5).

## Defects (ranked)

### HIGH
1. **Application-level rejoin republishes a stopped microphone track** (owner: frontend-dev). `frontend/src/session/controller.ts:191-194` (`connectTransport`) re-publishes `this.micTrack` after `recover()`. `frontend/src/livekit/transport.ts:87` builds `new Room()` with default options, so livekit-client `Room.handleDisconnect(true)` calls `unpublishTrack(track, true)` and `track.stop()` on every local track (`node_modules/livekit-client/src/room/Room.ts:1831-1857`, `participant/LocalParticipant.ts:1608-1612`) after a server-initiated disconnect. `recover()` is entered only from that path, so the rejoin publishes an ended `MediaStreamTrack` and the agent hears silence after "recovered". The device-loss watcher does not fire (`stop()` emits no `ended`). No unit test uses real livekit-client semantics. Fix: re-acquire the microphone before republishing (or check `readyState`), or set `stopLocalTrackOnUnpublish: false`; add a test. Not reproduced in a real browser (no server-drop harness); evidence is SDK source.

### MEDIUM
2. **Exit gate not proven end to end in a real browser** (owner: frontend-dev / orchestrator). The single Playwright test is mocked and covers only the failure path. A manual browser run against the real worker is required (see below).
3. **Playwright config not compliant with the QA policy** (owner: frontend-dev). `frontend/playwright.config.ts` lacks `trace: 'retain-on-failure'`, `screenshot: 'only-on-failure'`, `video: 'off'`, an `outputDir` under `outputs/`, and `--use-file-for-fake-audio-capture=<fixture.wav>`. Default `test-results/` lands in `frontend/`.
4. **Mic device loss does not end or fail the live session** (owner: frontend-dev). `controller.ts:135-141` only sets mic status `lost` and keeps the session running with a dead track until maximum duration or manual stop. Consider ending with a dedicated reason or a blocking state.
5. **No shared golden fixture between the TS encoder and Python decoder** (owner: frontend-dev and backend-dev). Each side is tested against hand-written payloads; only the Python stand-in browser (`tests/support/livekit_browser.py`) reaches the real worker. Add a JSON fixture consumed by both suites.
6. **LiveKit usage/cost not recorded for real runs** (owner: backend-dev, WP11). The docs/14 §12 cost line asks for this before real cloud testing; deferred. Real runs were tiny (a few short rooms in this verification).
7. **Blanket ResourceWarning suppression** (owner: backend-dev). `tests/integration/persistence/test_livekit_media.py:52-53` and `tests/integration/livekit/test_livekit_media_transport.py:44-45` ignore all `ResourceWarning` and unraisable warnings for the whole module. Broader than the claimed narrow socket-only filter in `tests/conftest.py` (that one is correctly scoped to `atlas`-marked tests and socket warnings). Narrow to the unclosed event loop/socket messages.

### LOW
8. When the worker ends a session normally and the room is closed, browser `recover()` requests a fresh token, gets a non-retryable terminal error, then `abort()` reports `failed` and posts a `transport_error` end to an already-terminal session (`controller.ts:264-289`, `:394-402`). The UI shows failure for a normal agent-side end (owner: frontend-dev).
9. `MediaCheck` sends `completed` right after the last frame is queued, and browser progress is elapsed-time based (evidence only, acceptable for the media check, `media_check.py:burst`). `mic_peak` never decays (`media_check.py:_listen`).
10. `client.latency_sample` is decoded and limited to one per turn (`session.py:_first_latency_sample`) but no component consumes it and the frontend never sends it (later WP).
11. Frontend bundle exceeds 500 kB (livekit-client); no action for R&D.
12. `-m livekit` does not run the dispatched-job test (needs `-m "livekit and atlas"` because the worker writes Atlas). Note this in the test module docstring.
13. Two stale failed `voice_sessions` remain in Atlas from earlier implementer runs (count only; not deleted by this verification).

No CRITICAL defects. No docs/14 §19 stop condition was triggered (no secrets in output, no recording, no broader permissions, no new dependency).
